Function composition lets us build new functions by passing one function's result to the next. In the [currying post](/posts/curried-functions-in-typescript), we chose a transformation before supplying the data. Here, we'll connect transformations while keeping their types intact.

## One transformation after another

Let's start with two functions we can combine.

  id="composition-sequential"

Both give us `[30]`. First we add ten, then we double the result. The second version combines those operations in a single callback. What you may not have realized is that we just tested out the **composition law** from algebra.

$$
(f \circ g)(x) = f(g(x))
$$

In the code example, `addTen` would be `g` and `double` would be `f`. This is relevant because, when composing pure functions together, we can model our software like a basic algebra problem.

Enough of the math talk though, let's move forward and create a new function that performs these transformations in one go.

## Connecting two functions with pipe2

`pipe2` takes two functions and returns a function that runs them in the order we pass them in.

<TsSandbox
  id="composition-pipe2"
  title="Build a function with pipe2"
  code={pipeExample}
/>

`A` is the input type, and `C` is the return type. The shared `B` connects the first function's output to the second function's input. That's how TypeScript checks that the two functions fit together.

Here, all three types are `number`. TypeScript infers `(value: number) => number` for `addTenThenDouble`, so we can reuse it wherever we need that transformation.

## The same steps with compose2

`compose2` lets us write the functions in reverse order, or bottom-up, matching the composition law we looked at earlier. The rightmost function runs first.

<TsSandbox
  id="composition-compose2"

/>

The implementation is the same. We just changed the order of the parameters, so `compose2(double, addTen)` runs the same steps as `pipe2(addTen, double)`.

### When types aren't enough

The order we pass functions in very much matters though. `pipe2(double, addTen)(5)` gives us `20`. Both orders accept and return numbers, so both type-check. To ensure we're getting the output we intend, we can use a test to check our result.

Run the test below. Swap `addTen` and `double`, then run it again. The types still fit, but we'll see the assertion fail because the result is `20`.

TypeScript is very useful, but it's still important to test our logic and verify that our code behaves as intended. As Eric Elliott so eloquently puts it, ["Type correctness does not guarantee program correctness."](https://medium.com/javascript-scene/the-shocking-secret-about-static-types-514d39bf30a3)
