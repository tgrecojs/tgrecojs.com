Function composition lets us build new functions by passing one function’s result to the next. This post picks up where we left off in the [currying post](/posts/curried-functions-in-typescript), where we learned how to preserve types when choosing a transformation before supplying its data. Here, we’ll build on that to connect multiple functions into pipelines while keeping their types intact.

## One transformation after another

Let's start with two functions we can combine and see how two different approaches arrive at `[30]`.

The first approach adds ten to each item in the `values` array, then uses a second `.map()` to double each result. The second approach combines those operations in a single callback. What you may not have realized is that we just tested out the **composition law** from algebra.

$$
(f \circ g)(x) = f(g(x))
$$

In the code example, `addTen` would be `g` and `double` would be `f`. This is relevant because, when composing pure functions together, we can model our software like a basic algebra problem.

### When types aren't enough

We've seen firsthand how TypeScript checks that each function in the pipeline receives the correct input type. While there's no denying that this is useful, it's no substitute for tests. We could mistakenly pass functions in the wrong order, and because they both accept and return `number`, TypeScript will have no problem compiling our code. This is why it's important to pair our logic with tests to verify that the output matches our intended behavior.

Let's take a quick look at a code block showing this pitfall. TypeScript reports no errors, yet running the code below fails the `strictEqual` assertion because the result is `20` instead of `30`.
