How can we type a function so that it accepts different types without forgetting which type a particular call receives?

The answer is *generics*. Generics let us describe a relationship between types, allowing functions to process inputs and produce outputs of varying shapes while preserving the information that connects them.

## Our first generic

{ /* PFU: Update `identity` to point to fp 101 posts introducing it */}
The starting point for us will be to describe the identity function:

```js
const identity = value => value;
```

TypeScript gives us a few options for typing this. We can use `unknown`, `any`, or a generic type parameter. The runtime behavior of identity stays the same, but what doesn't stay the same is what changes the information the TypeScript compiler provides about its result.

## Returning unknown

We can accept an `unknown` value and return it. At runtime, passing in a string still gives us that string back. But the return type tells us that the result is unknown.

The last line intentionally produces a type error: the compiler won't allow us to call `toUpperCase` on a value whose type is `unknown`. We could check whether the result is a `string`, but the caller already supplied a `string`. We have lost that relationship in the signature.

## Returning `any`

Using `any` makes the error disappear, but it also allows an operation that does not make sense for the supplied value:

<TsSandbox id="generics-identity-any" title="Identity returning any" code={identityAny} />

This code type-checks, but once it's executed, the call to `toFixed` fails because the string `thomas` does not have that number method. `any` has removed the check that would have caught the mistake.

## Preserving the type

The question is: how to retain the input type rather than discard it or turn off checking. This is where a type parameter helps:

```ts
const identity = <T>(value: T): T => value;
```

The above code block expresses the following:

- `<T>` declares a type parameter for the function.
- `value: T` gives the input that type.
- `: T` gives the output the same type.

For `identity`, we want the result to preserve the input’s type. Using `T` for both the parameter and return type describes that relationship. TypeScript can infer `T` from the argument, so we usually don’t need to specify it ourselves.

<TsSandbox id="generics-identity" title="Identity preserving its input type" code={identityGeneric} />

Running the code above shows that the `result` assignment can access all of the methods globally available for `string` types, and the `year` assignmentcan access all of the methods globally available for `number`. Now we're finally getting somewhere! { /* Now we're finally getting back to our happy place. */}
