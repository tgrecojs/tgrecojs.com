> Working outline. Keep fixed-length composition as the explanation of the relationship, and give the variadic implementation its own clearly marked section.

## The question

Can the compiler check every connection between transformations and infer the function produced by their composition?

## Start with the runtime order

For pipe(f, g), evaluate g(f(value)). For compose(g, f), evaluate the same expression. Use unequal input/output types so swapping the order produces a visible mistake. State that these helpers build a function; some libraries call this form flow and reserve pipe for a value-first API.

## Link the three types in the two-function version

```ts
const pipe2 = <A, B, C>(
  first: (value: A) => B,
  second: (value: B) => C
) => (value: A): C => second(first(value));

const compose2 = <A, B, C>(
  second: (value: B) => C,
  first: (value: A) => B
) => (value: A): C => second(first(value));
```

Explain A to B to C. Start with concrete transformations and verify both helpers. Then test pipe2(singleton, box) separately: its generic relationship survives this higher-order signature. The runtime-equivalent compose2(box, singleton) is a separate inference experiment, not an automatic guarantee. With the signature above, the generic compose call fails inference in TypeScript 5.9.3; use concrete callback types or explicit type arguments to demonstrate its runtime order before exploring that limitation. Reversing singleton and box changes the intended value shape, and each example must call its own returned function.

## Name the data, or leave it out

Introduce point-free style once `pipe2` works. This section is moved from the curried functions draft. Define `trim` and `toLowerCase` as one-argument string functions first, and link to the curried functions post once it is published.

```ts
// names the data
const normalizeExplicit = (value: string) => toLowerCase(trim(value));

// point-free: never names it
const normalizePointFree = pipe2(trim, toLowerCase);
```

Point-free functions are functions that are "free" of the points (data) they operate on. They don't need the data at the time of creation. It's like a team of functions. They're ready to operate at the moment they get called into the game.

`normalizePointFree` is point-free with respect to the string: it does not explicitly name or forward that parameter. It still accepts a string when called. The inner callbacks name their own `value`, so the point-free description applies to the outer definition, not every function inside it.

These ideas describe different parts of the example. `pipe2` is curried-style: it takes its functions first and returns a function that waits for the value. Supplying only the functions is partial application. Defining `normalizePointFree` without an explicit string parameter is point-free style.

Confirm TypeScript still infers `(value: string) => string` for both versions. Tie this to the generic `singleton`/`box` test below: point-free is where generic inference gets fragile, so keep that experiment separate.

## Add one more transformation

Use a string to number to boolean chain. Compare the correct inferred signature with a deliberately mismatched link. Keep generic singleton/box preservation as a separate test from concrete string/number transformations.

## Extend to variadic composition

Separate accepting a runtime list of functions from statically checking a heterogeneous tuple of functions. Show why replacing the tuple with an array of unknown-returning functions forgets the connections. Decide and document empty-pipeline behavior, then check one, three, and several stages, incompatible neighbors, and the same operations in reverse compose order.

Treat recursive tuple/conditional types and generic inference limits as an advanced section or a standalone follow-up if they overwhelm the main example. Do not require mastery of that implementation before readers can understand the validator factory: its outer pipeline needs only normalization followed by validation. Avoid promising literally unbounded compiler recursion or universal inference for arbitrary generic callbacks.
